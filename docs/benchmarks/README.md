# Phase 6 성능 측정 (2026-10-16)

## 재현

```bash
npm run bench:core
npm run bench:build
npm run bench:serve
```

`http://127.0.0.1:4174/Architecture-/benchmarks/index.html`에서 전체 측정을 시작한다. 별도 production 진입점이며 정상 배포에는 측정 패널을 넣지 않는다. 측정은 해당 테스트 페이지의 그래프를 교체한다. JSON fixture가 필요하면 `npm run bench:fixtures`를 실행한다. core 보고서 기본 경로는 core-latest.json이며 `BENCH_REPORT` 환경 변수로 바꿀 수 있다. baseline/final 파일은 이번 실측을 보존한다.

## 환경과 방법

Windows 10.0.26200, AMD Ryzen AI 7 350 / Radeon 860M, Node 24.12.0, 내장 Chromium, 실제 1280×900 viewport. browser JSON에 UA/DPR/visibility/프레임 보정치를 기록했다. 프레임 간격 약 4.2ms인 환경이므로 60Hz 기기와 직접 비교하지 않는다. chain은 순차 연결, dense는 건너뛰기/행 연결/순환을 추가하여 300노드에서 888연결이다. 고정 grid를 사용한다.

core는 warmup 제외 15회, 정렬 5회 표본의 중앙값/p95/max다. browser 선택 10회, store 위치 변경 30프레임, 정렬 2회, PNG 각 범위 1회다. 로드/선택/정렬은 두 번의 requestAnimationFrame 후 측정하고 drag는 프레임 간격이다. 물리 포인터 지연이나 모든 렌더가 끝나는 시간의 보장은 아니다. 첫 정렬은 엔진 요청/시작 비용을 포함한다. browser-worker는 Worker/참조 보존까지만 적용한 중간 결과다.

전체 long task 합은 44323 → 15063ms, 최대 6732 → 2512ms였다. 여러 PNG·메인 스레드 직렬화도 포함하므로 ELK만의 개선으로 해석하지 않는다. dense300 JS heap의 로드/drag/정렬/현재PNG/전체PNG 스냅샷은 baseline 약 70.5/102/132.8/203.4/329.9MiB, final 70.3/90.6/117.9/64.2/94.6MiB다. GC 시점이 다르며 native canvas/GPU/최대/유지 메모리를 측정하지 않았다. 메모리 누수 해소나 최대 메모리 보장을 주장하지 않는다.

## core와 번들

dense300 중앙값: 선택30회 22.02 → 0.16ms, drag30회 34.86 → 10.88ms, encode 2.74 → 2.34ms, decode 11.13 → 7.84ms, JSON export 0.89 → 1.28ms, import 5.65 → 3.66ms, 정렬 1090.69 → 945.52ms. 압축 알고리즘은 바꾸지 않았고 미세한 직렬화 차이는 실행 편차도 포함한다. 주요 변경은 노드/엣지 참조 보존과 Map 조회다.

정상 앱 초기 JS 1970.46KB/gzip613.34KB → 542.16KB/gzip173.06KB. ELK API 4.44KB와 classic Worker1593.71KB를 처음 정렬할 때 읽는다. Worker 없는 환경용 bundled fallback1432.24KB도 별도 출력된다. 전체 파일 크기/정렬 첫 요청 비용이 사라진 것은 아니다. 500KB chunk 경고는 남는다.

## 수치 목표와 판정

baseline을 확인한 뒤 이번 환경에서 쓸 진단 목표를 정했다. 기기별 SLA나 CI 시간 assertion이 아니다.

| 항목                               | 목표               | final                                                  |
| ---------------------------------- | ------------------ | ------------------------------------------------------ |
| ≤100노드 선택 p95                  | ≤100ms             | 통과                                                   |
| ≤100노드 drag p95                  | ≤34ms              | 통과                                                   |
| 300노드 로드 / 선택 p95 / drag p95 | ≤1000 / 200 / 80ms | 통과                                                   |
| dense300 정렬                      | ≤2000ms            | 통과                                                   |
| 현재 PNG 각 case                   | ≤1500ms            | 통과                                                   |
| 전체 PNG 각 case                   | ≤6000ms            | chain100 단일 관측 및 반복 최대 실패, 반복 중앙값 통과 |

300노드 60fps, 모든 동작 개선, 전체 PNG 시간 목표 달성을 완료 처리하지 않는다. Worker로 계산을 분리하고 취소/오류/30초 timeout 후 재시작할 수 있다. 출력 닫기는 결과를 버리며 진행 중 rasterization을 강제 중단하지 않는다.

## 접근성과 브라우저 범위

a11y-dark/light JSON은 표시된 조작 요소 이름 누락 0, 주요 text/secondary/accent와 surface 및 text/muted 네 쌍의 대비 ≥4.5를 확인한다. 명칭 검사와 토큰 대비만 다루며 전체 WCAG/스크린리더 인증이 아니다. React Flow 노드/연결 이름과 키보드 안내/이동 live 안내를 한국어로 제공한다. reduced-motion은 기존 CSS를 유지하며 해당 OS 설정의 실제 실행은 미검증이다.

실제 Chromium에서 샘플 노드 Enter선택, 오른쪽 5px 이동, Delete삭제, Undo복원/이동복원, Worker정렬 적용, dense300 JSON 가져오기와 확인, 정렬 시작→취소 후 grid 위치 보존을 확인했다. Firefox/Safari/Edge, 물리 터치/스크린리더와 원격 배포는 미검증이다. Phase 7에서 배포/사용자 문서와 함께 보완한다.
